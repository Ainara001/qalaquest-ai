## 2. Ограничения среды, в которой идёт работа

- На этой машине **нет Docker, PostgreSQL и ключа Gemini**, а база с 1030 POI осталась на машине, где делались этапы 2–5. Поэтому полный end-to-end прогон (реальные POI + Valhalla + Gemini) здесь невозможен.
- Что проверяется здесь: сборка фронтенда (`tsc` + `vite`), импорт и чистая логика бэкенда (Python 3.13, юнит-проверки алгоритмов на тестовых кандидатах), вёрстка в браузере на ширинах 320/375/390/430 px с временной заглушкой API **вне репозитория** (только для проверки UI, в продукт не попадает).
- Всё, что не удалось проверить на реальных данных, помечается в `PROJECT_STATUS.md` как непроверенное.

### Принципы, которые соблюдаются во всех фазах

- RAG, маршрутизатор и БД не переписываются: новые функции используют существующие `retrieve`, `PersonalizationService`, `RoutePlanningService`, `WeatherService`.
- Обычный поиск по названию не обращается к LLM; рекомендации по настроению на карте — тоже без LLM (`/api/ai/search`, детерминированное ранжирование).
- Ни один факт о месте не выдумывается: названия, координаты, часы и т. д. — только из БД; настроение — предпочтение для ранжирования, а не свойство места.
- Пользовательские изменения не удаляются; `main` не трогается.
