# Доступность: данные и ограничения

## Что реализовано
- **Источник:** только реальные теги OSM самого места (импорт сохраняет все теги в `pois.tags`): `wheelchair`, `ramp`, `ramp:wheelchair`, `wheelchair:description`, `toilets:wheelchair`, `elevator`, `entrance`, `step_count`, `handrail`, `automatic_door`, `door` (`backend/app/core/accessibility.py`).
- **Вход и место:** `wheelchair=yes/designated` → «подтверждено в OSM», `limited` → «частично», `no` → «недоступно», нет тега → «доступность не подтверждена». `wheelchair=yes` **не** считается доказательством пандуса: пандус показываем, только если есть тег `ramp*`.
- **Путь:** всегда «не проверен на безбарьерность». Маршрут строится Valhalla с профилем `wheelchair` (обходит известные лестницы), но данных о бордюрах, ступенях и покрытии в Астане мало. В маршруте показывается предупреждение, безопасность пути не гарантируется.
- **Фильтр «Доступно»** (чип на карте, добровольно, без аккаунта, сбрасывается одним нажатием): только места с подтверждённым тегом; если их нет — честное «мест с отмеченной доступностью не найдено».

## Чего нет и как добавить
1. Импорт отдельных объектов OSM: входы (`entrance=*` + `wheelchair`), пандусы, лифты, ступени (`highway=steps`), бордюры (`kerb=*`). Отдельная таблица `accessibility_features` (osm_type/osm_id, точка, тег, `source_url`, `last_checked_at`, статус).
2. Значки пандусов и доступных входов на карте только по реальной точке. Вход с неизвестным положением не отмечаем.
3. Проверка пути: `trace_attributes` Valhalla по построенной линии → сегменты с известными `surface/smoothness/kerb/incline` и сегменты без данных (подсвечивать).
4. Официальные данные (паспорта доступности объектов акимата), если будут доступны по договору.
